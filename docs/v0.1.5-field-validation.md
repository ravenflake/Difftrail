# Difftrail v0.1.5 real-outcome validation checklist

This gate turns naturally occurring incident outcomes into evidence about the
deterministic ranking rules. It does not let Difftrail infer causality. Complete
the v0.1.4 install, watcher, and privacy checks as applicable; this checklist
adds the v0.1.5 outcome-quality checks.

## Runtime regression checks

- Check Collection & system and `validate-host --json` for separate runtime
  failure counts. A successful latest scan must not hide a retained pre-scan
  schema/startup failure; unavailable logs must not become an uptime claim.
- Observe an ordinary device disconnect/reconnect. Device transitions remain
  visible, but unchanged driver associations must not produce install/remove
  notifications. A changed version must still appear when observed again.
- Verify the status companion starts when the desktop opens, remains after
  the window closes, and records `exited_by_user` when explicitly exited.
- Build with `python scripts/check_release_metadata.py --runtime`. Archive
  stale ignored `_build_version.py` / `tauri.build.conf.json` inputs before a
  release build. Intentional development builds require
  `DIFFTRAIL_ALLOW_BUILD_STAMP=1` and the matching Tauri `--config` argument.
- Keep earlier journal evidence intact. Historical driver presence noise is
  not silently deleted or relabeled by this fix. Fresh multi-day observations
  and independently verified incident outcomes are still required.

## Record only verified outcomes

Use exactly one outcome for each completed review:

- `confirmed_cause`: an independently verified cause that appears in the ranked
  leads. Select its event ID and how it was verified.
- `useful_lead`: a ranked change helped the investigation but was not verified as
  the cause.
- `irrelevant_lead`: testing showed a selected ranked change was irrelevant.
- `uncaptured_cause`: the cause became known but no ranked lead represents it.
  Record the structured collection or window gap.
- `unknown`: the investigation is unresolved or lacks enough information.

Do not label a cause confirmed because it ranked first, occurred nearby, or
sounds plausible. Reproduction, resolution after a controlled change, or an
independent diagnostic can support the user label; the engine itself cannot.

The desktop outcome form is preferred. The equivalent CLI examples are:

```powershell
python -m difftrail --db "$env:LOCALAPPDATA\Difftrail\difftrail.db" feedback <incident-id> --outcome confirmed_cause --event-id <event-id> --reason reproduced
python -m difftrail --db "$env:LOCALAPPDATA\Difftrail\difftrail.db" feedback <incident-id> --outcome useful_lead --event-id <event-id> --reason narrowed_investigation
python -m difftrail --db "$env:LOCALAPPDATA\Difftrail\difftrail.db" feedback <incident-id> --outcome uncaptured_cause --reason provider_gap
```

## Check repeatability and privacy

1. Save an outcome for a lower-ranked confirmed cause and verify the review
   shows the original one-based rank.
2. Rerun or update the evidence review. The recorded outcome rank must remain
   the rank observed when feedback was saved until the user saves a new outcome.
3. Export and validate a diagnostic bundle. Its feedback record may contain only
   the outcome, opaque event ID, recorded time, numeric rank, and controlled
   reason code—never a username, path, raw message, or free-form cause account.
4. Run `validate-host --json` twice against an unchanged journal. Confirmed-cause
   top-1/top-3, known-cause capture, rank distributions, and reason distributions
   must be identical.
5. Confirm older helpful feedback appears as `useful_lead` with
   `legacy_unspecified`, never as `confirmed_cause`.

## Interpretation gate

Collect at least five resolved or explicitly unknown real reviews before drawing
product conclusions, including one confirmed cause below rank one, one irrelevant
ranked lead, and one uncaptured cause if naturally available. Treat small cohorts
as directional. Improve a rule only when the stored evidence and outcome reason
make the failure repeatable, then add a synthetic ground-truth regression with
distractors and counter-evidence. Never tune against private descriptions or
claim a causal-accuracy rate from user labels alone.
